# kubyshka-bots

Два Telegram-бота + мини-апп для проекта «Кубышка» (FinAssist). Отдельный
репозиторий — не часть FinAssist/Finik-backend, но читает `Docs/*.md` оттуда
для контекста.

## Бот 1 — `team_bot` (командный чат)

| Команда | Что делает |
|---|---|
| `/start`, `/help` | Список команд |
| `/task <текст>` | Записывает задачу на общую доску (SQLite). Можно ответить `/task` на чужое сообщение или фото с подписью — возьмёт текст/подпись оттуда |
| `/tasks` | Показывает незавершённые задачи с номерами и тем, кто уже взял |
| `/mytasks` | Задачи, которые взял именно спрашивающий |
| `/claim`, `/unclaim`, `/testing <номер>` | Fallback-команды для доски без мини-аппа (взять/отпустить/на тестирование) |
| `/done <номер>` | Отмечает задачу выполненной |
| `/comment <номер> <текст>` | Комментарий к задаче без захода в мини-апп |
| `/rename <номер> <текст>` | Переименовать задачу |
| `/board` | Открывает мини-апп с доской задач (только в личке с ботом — см. ниже) |
| `/remindnow` | Присылает дайджест открытых задач сейчас же (обычно раз в день сам — см. «Ежедневные напоминания») |
| `/ask <вопрос>` | Отвечает про проект с контекстом из `Docs/*.md` FinAssist + Finik-backend |
| (упоминание в группе / любое сообщение в личке) | Отвечает как ассистент без `/ask` — в группе только если обратились (реплай боту или `@бот`), в личке на любое сообщение |
| `/id` | Показывает ID текущего чата (нужно один раз при настройке `TEAM_CHAT_ID`) |

Команды `/claim`/`/unclaim`/`/testing`/`/comment`/`/rename` дублируют действия
мини-аппа в чате — так доска остаётся полностью рабочей, даже если
`WEBAPP_URL` временно недоступен (например, слетел туннель). Автодополнение
команд включено (`bot.set_my_commands()`), Telegram покажет список при вводе «/».

### Доска задач — мини-апп (`webapp/`)

`/board` в личном чате с ботом открывает Telegram Mini App — веб-страницу
внутри Telegram с общим списком задач в реальном времени (поллинг раз в 5с):
взять задачу себе, отметить выполненной, вернуть в работу, оставить комментарий.
Одна версия на всех — все видят одно и то же состояние.

- **Статусы задачи**: открыта → (взял кто-то) → на тестировании → готово.
  Переход в «на тестировании» и обратно в работу доступен в любой момент —
  это не строгий воркфлоу, а подсказка для команды, где реально находится
  задача (полоска слева в списке и плашка статуса в карточке меняют цвет).
- **Карточка задачи**: тап по строке в списке открывает полноэкранную
  карточку — полное описание (редактируется прямо там), переименование
  (значок ✏️ у заголовка), вся история комментариев, те же действия
  (взять/тестирование/готово), что и в списке. Внутри Telegram использует
  нативную кнопку «Назад» (`Telegram.WebApp.BackButton`) вместо своей — так
  выглядит как часть интерфейса Telegram, а не отдельная страница.
- **Готовые задачи старше недели скрыты по умолчанию** (`done_within_days=7`
  в `shared/task_store.py`) — доска не должна расти в бесконечную ленту.
  Ссылка «Показать всю историю» под счётчиками переключает на полный список.
- **Хранилище — SQLite (`shared/task_store.py`), не iCloud Reminders.** У
  VTODO нет полей "кто взял"/комментарии, а несколько человек должны видеть
  и менять одну задачу одновременно — CalDAV для этого не подходит. SQLite
  как источник правды, Напоминания остаются best-effort зеркалом (см. ниже).
- **`/task` пишет в оба места**: сначала на доску (это источник правды),
  затем best-effort пытается создать зеркальную запись в iCloud Reminders —
  если зеркалирование упало (список не расшарен, неверный пароль), сама
  задача всё равно записана на доску, ничего не теряется. `/done` аналогично
  зеркалит завершение в Reminders, если знает uid зеркальной записи.
- **Backend — FastAPI (`webapp/server.py`)**, отдаёт статику `webapp/static/`
  и JSON API (`/api/tasks/...`). Каждый запрос проверяет Telegram `initData`
  (`shared/telegram_webapp_auth.py`) — HMAC-подпись на секрете от токена
  бота, без которой чужой человек не мог бы дёргать API от чужого имени.
- **Деплой отдельно от team_bot возможен**: `webapp/server.py` требует только
  `TEAM_BOT_TOKEN` (для проверки initData) и `TASKS_DB_PATH` — не тянет
  iCloud-креды/докс-контекст, которые нужны только team_bot.
- **Нужен публичный https-адрес** (`WEBAPP_URL` в `.env`) — Telegram не
  открывает `web_app`-кнопки на http/localhost. Пока не задеплоено — `/board`
  честно говорит об этом вместо ошибки. Локально можно поднять туннель
  (ngrok/Cloudflare Tunnel) на `WEBAPP_PORT` для проверки на реальном устройстве.
- Запуск локально: `python -m uvicorn webapp.server:app --port 8080` (или
  `python webapp/server.py`, если `WEBAPP_PORT` задан в `.env`).

### Ежедневные напоминания

Раз в день (час задаётся `TEAM_REMINDER_HOUR`, по умолчанию 10 по местному
времени машины) team_bot сам присылает в `TEAM_CHAT_ID` дайджест открытых
задач — «Кириллу сегодня нужно сделать X» — сгруппированный по тому, кто
взял задачу, плюс отдельный список того, что пока никто не взял. Если
открытых задач нет, дайджест не шлётся (не спамим «всё сделано» ради самого
себя). Настоящее Telegram-упоминание (кликабельное, с уведомлением) — не
просто текст с именем: используется `claimed_by_user_id`, записанный при
`claim` в мини-аппе. `/remindnow` шлёт тот же дайджест сразу — удобно
проверить формат, не дожидаясь `TEAM_REMINDER_HOUR`. Не персистится между
рестартами бота (не критичное уведомление, простой ежедневный sleep-цикл).

### Контекст ассистента

Кроме базового набора (`BACKLOG.md`, `AI_CHANGELOG.md`, `RELEASE_NOTES.md`,
`API_CONTRACT.md`, `ARCHITECTURE.md`/`ARCHITECTURE_DEEP_DIVE.md` — грузится
всегда, когда контекст вообще нужен), ассистент **тематически** подключает
доп. файлы FinAssist по ключевым словам в вопросе (`shared/docs_context.py`,
`topic_context_files`): онбординг → `ONBOARDING_FLOW.md`/`ONBOARDING_GROWTH_PLAN.md`,
цели → `GOALS_SCREEN.md`/`SEMANTICS_GOALS.md`, зарплата → `PAYCHECK_FEATURE.md`
и т.д. Эти файлы получают вдвое больший бюджет символов, чем базовые — раз уж
они явно релевантны вопросу. Бюджет между файлами делится не поровну, а
пропорционально после урезания (если суммарно не влезло) — чтобы файл никогда
не пропадал из контекста ЦЕЛИКОМ только из-за порядка обработки (было
регрессией: второй репозиторий обрабатывается последним и терял свои файлы
первым при банальной обрезке хвоста).

### Экономия токенов

Команд-бот задуман как дешёвый хелпер, а не полноценный ассистент с полным
контекстом на каждое сообщение:

- **Контекст проекта — только когда реально нужен.** Простая эвристика
  (`shared/context_heuristic.py`) по ключевым словам + длине вопроса решает,
  грузить ли `Docs/*.md` обоих репо. `/ask` — явное намерение, контекст грузится
  всегда; обращение по имени/реплай в чате — только если похоже на предметный
  вопрос. "Привет"/"спасибо" не тратят токены на контекст.
- **Отдельная модель для команд-бота** (`TEAM_BOT_MODEL`) — можно посадить на
  более дешёвую/быструю модель, не трогая ту, что настроена для канала
  (`OPENAI_MODEL`). Пусто → берётся общая модель.
- **Лимит вопросов в час на чат** (`TEAM_BOT_MAX_QUESTIONS_PER_HOUR`, по
  умолчанию 30) — защита от случайного/нарочного вычерпывания бюджета одним
  болтливым чатом. 0 — выключить.
- Сокращённый бюджет контекста (9000 символов вместо дефолтных 12000) и
  ограничение ответа (500 токенов, см. ниже про reasoning-модели) —
  команд-бот отвечает по делу, не эссе.
- **`OPENAI_REASONING_EFFORT=minimal`** (по умолчанию, `shared/config.py`) —
  gpt-5-mini тратит часть `max_tokens` на скрытые reasoning-токены ДО
  видимого ответа; "minimal" убирает этот налог в большинстве случаев
  (проверено реальными вызовами: `reasoning_tokens=0` вместо сотен). Эффект
  прямой: меньше токенов на тот же ответ = меньше денег за вызов.
- **Автоматический ретрай при пустом ответе** (`shared/llm_client.py`) — даже
  с "minimal" reasoning-модель иногда (нестабильно, зависит от объёма
  контекста) всё равно гасит весь бюджет на reasoning и возвращает пустую
  строку. Вместо того чтобы закладывать большой `max_tokens` в КАЖДЫЙ
  вызов "на всякий случай" (дорого постоянно), при пустом ответе делаем
  ОДИН повторный вызов с бюджетом ×3 (потолок 2000) — платим больше только
  в те редкие разы, когда это реально понадобилось. Обычный короткий вопрос
  без контекста — один дешёвый вызов, как и раньше.

**Настройка списка Напоминаний (один раз, руками):**
1. На iPhone владельца (Apple ID из `.env`) — приложение «Напоминания» → создать
   список «Кубышка — задачи» → «Поделиться списком» → добавить команду.
2. На appleid.apple.com → Sign-In and Security → App-Specific Passwords →
   сгенерировать пароль для этого бота (НЕ основной пароль Apple ID).

## Бот 2 — `channel_bot` (публичный канал)

| Команда | Что делает |
|---|---|
| `/addtopic <тема>` | Добавляет тему в очередь постов |
| `/queue` | Показывает очередь тем с номерами |
| `/removetopic <номер>` | Удаляет тему из очереди |
| `/preview` | Генерирует и показывает следующий пост, НЕ публикуя и не трогая очередь/changelog-состояние |
| `/postnow` | Публикует пост немедленно, не дожидаясь расписания (для теста/ручного триггера) |
| `/pause`, `/resume` | Приостановить/возобновить автопостинг (`/postnow` продолжает работать и на паузе) |
| `/status` | Пауза, время и заголовок последнего поста, очередь, интервал, время до следующего автопоста, ответы в обсуждении |
| `/id` | Показывает ID текущего чата (для настройки `CHANNEL_ID`/`DISCUSSION_CHAT_ID`) |

Команды кроме `/id` работают только из `CHANNEL_ADMIN_CHAT_ID` (если задан) —
без него доступны из любого чата, что нормально для локальной разработки, но
не для продакшена с открытым чатом обсуждения. Рекомендуется указать туда тот
же чат, что `TEAM_CHAT_ID` у `team_bot`. Если `CHANNEL_ADMIN_CHAT_ID` задан,
Telegram показывает автодополнение админ-команд только в этом чате
(`BotCommandScopeChat`) — остальным чатам они всё равно недоступны.

- Постит автономно каждые `POST_INTERVAL_HOURS` часов. Источник темы —
  по приоритету: очередь тем (`/addtopic`) → неиспользованная запись
  `AI_CHANGELOG.md` (переформулированная в юзкейс) → тема, придуманная моделью
  самостоятельно по общему контексту проекта (в этом последнем случае — один
  LLM-вызов на "придумать тему и сразу написать пост", а не два раздельных —
  экономия токенов, т.к. это самый редкий и самый "тяжёлый по контексту" путь).
- **Формат поста — "джоба → фича"** (по итогам ревью с Кирилл): сначала в
  юмористической форме житейская проблема читателя с деньгами (без упоминания
  приложения), потом — что в «Кубышке» есть функция, которая её решает.
  Шутки мягкие, без осуждения читателя.
- **Иногда приглашает в бета-тест** (`BETA_INVITE_URL`, ~1 пост из 5,
  не выдумываем ссылку — пусто → приглашений не будет). Канал — единственная
  точка, куда вести людей из живого общения в чатах, максимум приглашение в
  бету, ничего агрессивнее.
- **Опциональный режим ревью** (`CHANNEL_REQUIRE_APPROVAL=1`, требует
  `CHANNEL_ADMIN_CHAT_ID`) — вместо немедленной публикации пост уходит в
  админ-чат с кнопками «✅ Опубликовать» / «🗑 Пропустить»; следующий цикл
  генерации не начинается, пока текущий черновик не получил решения. По
  умолчанию выключено — канал постит полностью автономно (осознанный выбор
  для нового бренд-голоса, см. «Известные ограничения»).
- При перезапуске бота НЕ постит сразу повторно, если предыдущий пост был
  недавно — ждёт остаток интервала (иначе частые рестарты выглядели бы как
  спам в канале).
- Если публикация упала (сеть, бот потерял права в канале) — повторная
  попытка через 30 минут, а не ожидание целого `POST_INTERVAL_HOURS` заново.
- Отвечает в чате обсуждения при канале (`DISCUSSION_CHAT_ID`), если он задан —
  на явные вопросы (есть «?») или упоминания «кубышк*» в тексте, не на каждую
  реплику подряд (иначе выглядело бы навязчиво в живом community-чате).
  Лимит `CHANNEL_DISCUSSION_MAX_REPLIES_PER_HOUR` (по умолчанию 10) НА
  ПОЛЬЗОВАТЕЛЯ — защита от одного спамящего "?" в публичном чате; при
  превышении бот просто молчит, не объясняя лимит незнакомым людям.

Instagram/Threads — не реализовано: официальная публикация требует настроенный
Meta Business/Creator аккаунт + Meta-приложение на стороне владельца бренда,
это отдельный этап после Telegram.

## Запуск локально

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить руками, ключи никогда не коммитить
cp channel_bot/topics_queue.example.json channel_bot/topics_queue.json

python -m team_bot.main      # в одном терминале
python -m channel_bot.main   # в другом
python -m uvicorn webapp.server:app --port 8080   # в третьем — доска задач
```

## Секреты
Ключи (Telegram-токены, OpenAI-ключ, Apple ID app-specific password) —
только в `.env` (не коммитится, см. `.gitignore`). Никогда не передавать их
текстом в чате/тикете — только через файл на диске.

## Известные ограничения
- Реактивные ответы в ЧУЖИХ (не своих) тредах/группах, рекомендующие продукт —
  сознательно не реализованы: для большинства платформ это выглядит как
  спам/astroturfing без явного раскрытия, что это бот. Если понадобится —
  отдельное обсуждение с явными предохранителями (частота, раскрытие, ручная
  модерация первое время).
- `channel_bot` публикует полностью автономно без ревью человеком — решение
  осознанное (принято явно), но для нового бренд-голоса стоит какое-то время
  посматривать за первыми постами вручную.
- **gpt-5-mini (или другая reasoning-модель) может вернуть пустой ответ.**
  Часть бюджета уходит на скрытые reasoning-токены ДО видимого текста —
  `OPENAI_REASONING_EFFORT=minimal` (см. «Экономия токенов») резко снижает
  это, но не гарантирует: с большим контекстом модель иногда всё равно
  гасит весь `max_tokens` на reasoning, причём НЕСТАБИЛЬНО (один и тот же
  запрос с одним и тем же бюджетом то срабатывал, то нет в тестах). Поэтому
  `shared/llm_client.py` сам ретраит пустой ответ с бюджетом ×3 (потолок
  2000) — это уже встроено, отдельно чинить не нужно. Если добавляешь новый
  вызов `llm.chat(...)`, не полагайся только на описание — проверь реальным
  вызовом API с реалистичным контекстом, пустая строка не бросает исключение.
